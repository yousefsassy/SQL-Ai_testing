Settings and measurement policy:
Temperature 0; maximum output 256 tokens; 60-second client timeout.
One model call per item, 50 items per model, sequential execution.
Shared prompt, parser, SQLite database, and result-comparison scorer.
Qwen think=False; no thinking option sent to other models.
No separate warm-up request. Model-call latency includes loading if needed.
The reported Qwen results are the latest requested rerun, with the model already
loaded. Both Qwen runs scored 47/50. Other models' final runs were not repeated.
Consequently loading state was not controlled equally; timing comparisons have
this limitation. No benchmarks were rerun while creating the report.
Generation tokens/s uses Ollama generation duration. Requests/hour uses elapsed
time for the full evaluation loop, including SQL scoring and Python overhead.

Cost assumption: EUR 0.20 per hardware hour, equally for all four models.
Hardware-only cost/1K = (0.20 / measured requests per hour) * 1000.
This is an assumed operating-cost scenario, not metered electricity spending.
Gemma's hourly-rate CSV cell remains blank from its original run; its cost/1K
cell was subsequently calculated using the same EUR 0.20/hour assumption.

Historical development hardware (not used in the final results table):

Those old development measurements are not combined with the current results.
